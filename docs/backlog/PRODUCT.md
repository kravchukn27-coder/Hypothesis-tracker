## PROD-030 — Синхронизировать Calendar и фильтр Experiments с текущим состоянием эксперимента

**Status:** TODO
**Priority:** MEDIUM
**Area:** Experiments & Calendar
**Type:** Data consistency
**Summary:** Статусный фильтр списка Experiments должен использовать текущий недельный этап, а архивные эксперименты не должны отображаться на Calendar.

**Description:** Source: user direction 2026-08-10. Для экспериментов
с `ExperimentWeekStage` плашка, сортировка и цвет строки в списке уже
используют текущий этап недели через `getCurrentWeekStage`, однако
Prisma-фильтр `?stage=` всё ещё читает производный кэш
`Experiment.stage` — этап последней запланированной недели. Привести
фильтр к тому же текущему этапу, не меняя legacy-поведение эксперимента
без недель. Также Calendar сейчас читает архивные эксперименты, хотя
архив должен скрывать объект из рабочих представлений, включая
Calendar. Обе части задачи относятся к единому правилу видимости и
актуального статуса эксперимента.

**Acceptance Criteria:**
- Фильтр Status на `/experiments` для week-tracked эксперимента
  использует тот же текущий этап, что плашка, цвет строки и сортировка:
  запись текущей недели; при её отсутствии — ближайшая предыдущая, либо
  первая будущая.
- Для legacy-эксперимента без `ExperimentWeekStage` фильтр Status
  продолжает использовать его поле `Experiment.stage`.
- Архивный эксперимент не показывается на `/calendar`, включая
  таймлайн, блок «Без дат», просроченные напоминания и легендарные
  фильтры.
- Разархивированный эксперимент снова становится доступен Calendar по
  существующим правилам расписания и Done-видимости.
- Изменение не меняет правила: предложение создать эксперимент из
  гипотезы появляется только для `PLANNED`, `IN_PROGRESS` и
  `ACCEPTED` при отсутствии экспериментов.
