## UI-040 — Показывать в Calendar эксперименты вне текущего окна недель

- **Status:** TODO
- **Priority:** High
- **Area:** UI / Calendar
- **Type:** Bug fix
- **Summary:** Эксперимент с реальными датами, которые целиком выпадают из текущего 8-недельного окна Calendar, сейчас молча пропадает из таблицы — не «без дат», а просто невидим. Добавить рядом с существующим сайдбаром «Эксперименты без даты» аналогичную секцию «Вне диапазона» с такими экспериментами.
- **Description:**
  Репортнуто пользователем: если у эксперимента даты (недельные стадии или legacy start/end) лежат целиком в прошлом или в будущем относительно текущего окна Calendar, `buildTimeline` (`src/lib/calendar.ts`, строка с `if (!cells.some((c) => c.stage !== null)) return null; // nothing in this window`) исключает такой эксперимент из `rows` — он не попадает ни в видимые строки таймлайна, ни в список `undated` (у него есть даты, просто не в этом окне). В обычном рабочем потоке (переход на "Сегодня" или через несколько недель вперёд-назад) эксперимент может выглядеть полностью потерянным, хотя он существует и активен. Технически найти такие эксперименты можно тем же способом, что и обнаружить пустой `rows`-результат — сравнить полный список `experiments`, переданный в `buildTimeline`, с теми, что вернулись в `rows`/`undated`.

  Обсуждались три варианта (см. историю чата): (1) компактные кликабельные индикаторы "← N раньше" / "N позже →" у краёв таймлайна, (2) отдельная боковая секция "Вне диапазона" по образцу уже существующего сайдбара "Эксперименты без даты" (UI-035/036), (3) полагаться на существующий режим "Показать все эксперименты". Пользователь выбрал вариант (2).
- **Acceptance Criteria:**
  - В обычном (не "Показать все эксперименты") режиме Calendar рядом с сайдбаром "Эксперименты без даты" появляется секция "Вне диапазона" (или другое понятное название), видимая только когда такие эксперименты есть в текущем окне.
  - В неё попадают эксперименты, у которых есть реальные даты (недельные стадии или legacy start/end), но ни одна их неделя не попадает в текущее видимое окно — то есть ровно те, что сейчас `buildTimeline` отбрасывает как `null`.
  - Карточка эксперимента в этой секции визуально согласована с существующими карточками "Без дат" (тот же стиль, UI-035/036), но не имеет drag-and-drop на неделю (эти эксперименты уже спланированы, в отличие от недатированных).
  - Клик по карточке переносит окно таймлайна на недели этого эксперимента — переиспользовать существующий механизм `experimentId` + `start` (тот же, что у ссылок из карточки гипотезы/эксперимента, UI-030).
  - Режим "Показать все эксперименты" и его список не меняются этой задачей.
  - Не меняются недельная сетка, доменная логика стадий и правила видимости (архив, скрытие Done).

- **Description:**

Причина расхождения — в разной композиции: колонка `Status` (`src/app/backlog/page.tsx` ~строка 207) собрана из двух отдельных элементов, `SortableHeader` (текст + стрелка сортировки) и следом `HeaderMultiFilter` с пустым `label=""` (рендерит только сам значок) — из-за пустого label порядок иконки внутри `HeaderMultiFilter` для Status визуально не виден. Это общий переиспользуемый компонент (тот же, что и у Status), так что фикс автоматически выравнивает и другие места, использующие `HeaderMultiFilter` с непустым `label` — например Calendar-фильтр «Автор» (`src/app/calendar/page.tsx`, `HeaderMultiFilter name="calendarAuthor" label="Автор" ...`), у которого сейчас та же проблема, хоть пользователь и не упомянул её явно на скриншоте.
- **Acceptance Criteria:**
  - В заголовке колонки Funnel Level в Backlog значок фильтра стоит справа от текста «Funnel Level», как у Status.
  - Поведение самого фильтра (открытие панели, выбор нескольких значений, применение через URL-параметры) не меняется — правка чисто визуальная.

## UI-023 — Сделать редактирование недельного плана в Calendar обнаружимым и безопасным

- **Status:** DONE
- **Priority:** Medium
- **Area:** UI / UX
- **Type:** Enhancement
- **Summary:** Сохранить прямое редактирование недельной сетки Calendar, но сделать перенос и изменение длительности понятными, подтверждаемыми и дополнить сетку вторичным сигналом нагрузки.
- **Description:**
  Calendar — основной desktop-инструмент для контроля текущих экспериментов, смены стадий, планирования следующих недель и оценки распределения нагрузки. Перенос и изменение длительности сначала показывают preview нового диапазона и требуют подтверждения; смена стадии одной недели остаётся быстрым действием с явной обратной связью. - **Acceptance Criteria:**
  - Клик по недельной ячейке, перенос блока и изменение его длительности остаются доступными без постоянных отдельных кнопок.
  - При наведении и keyboard-focus видно, что блок можно переносить, а его край — растягивать; пользователь получает краткую подсказку о доступных действиях в первом релевантном сценарии.
  - Перед сохранением переноса или изменения длительности показывается новый недельный диапазон и требуется явное подтверждение; отмена не меняет план.
  - После смены стадии недели, подтверждения изменения плана и ошибки сохранения пользователь получает однозначную контекстную обратную связь.
  - Заголовок каждой недели показывает компактное вторичное количество активных экспериментов, не нарушая приоритет даты и номера недели.
  - Сохраняются недельная модель данных, расчёт текущей стадии, фильтры, правила скрытия Done, редактирование из карточки эксперимента и существующий desktop-first подход.
  - Не меняются Prisma-схема, доменная логика, карточки экспериментов и мобильный вариант.

  - Визуальная иерархия строки делает статус главным, связь с экспериментом/гипотезой — вторым, а Score и Funnel Level — поддерживающими сигналами.
  - Длинные названия, комментарии и связанные значения можно прочитать полностью доступным способом без потери текущего контекста.
  - Список остаётся удобным для сканирования нескольких строк: header и колонки не теряют читаемость из-за чрезмерно ограниченной рабочей высоты.
  - Существующие URL-фильтры, сортировки, inline-редактирование статуса/стадии, bulk actions и правила жизненного цикла «гипотеза ↔ эксперимент» работают без изменения.
  - Не меняются карточки `/backlog/[id]` и `/experiments/[id]`, Prisma-схема, доменная логика и мобильный вариант.
