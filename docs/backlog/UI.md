# UI Backlog

## UI-023 — Зафиксировать эталонный размер таблиц Backlog, Experiments и Calendar

**Status:** TODO
**Priority:** MEDIUM
**Area:** UI
**Type:** Layout consistency
**Summary:** Текущий размер таблицы `/backlog` при двух записях —
эталон. Таблицы Backlog и Experiments, а также сетка Calendar должны
сохранять этот фиксированный размер независимо от числа записей и
длины их содержимого; не сжиматься на малом количестве строк и не
расширять контейнер из-за длинных значений.

**Description:** Source: user direction 2026-08-10. Сейчас Calendar
уже выглядит нужной длины, когда в нём две и более записи; это
состояние нужно сделать постоянным. Перед изменением измерить текущую
таблицу Backlog с двумя записями и использовать её как единственный
эталон для фиксированных габаритов всех трёх табличных поверхностей.
Содержимое ячеек должно оставаться читаемым в пределах выделенных
колонок (перенос или обрезка по существующему паттерну), без адаптивной
смены общего размера таблицы.

**Acceptance Criteria:**
- `/backlog` сохраняет эталонные ширину и высоту при 0, 1, 2 и большем
  числе строк; эталон — его текущее состояние с двумя записями.
- `/experiments` использует тот же фиксированный общий размер таблицы
  и не меняет его от количества или длины записей.
- Сетка `/calendar` имеет ту же фиксированную длину/высоту, что и
  эталонная таблица, включая состояния с малым числом экспериментов.
- Длинные названия, авторы, теги и комментарии не меняют общий размер
  таблиц; они обрабатываются внутри ячеек.
- Горизонтальная прокрутка на узком экране допустима, но адаптивная
  смена эталонных размеров таблиц недопустима.

## UI-024 — Открывать сфокусированный Calendar по ссылке на эксперимент

**Status:** TODO
**Priority:** MEDIUM
**Area:** UI
**Type:** Navigation
**Summary:** Переход к Calendar для конкретного эксперимента — с кнопки
на карточке или из колонки «Даты» списка — должен показывать только
этот эксперимент и давать явный способ вернуться к общему Calendar.

**Description:** Source: user directions 2026-08-10. Сейчас кнопка
«Показать на календаре» передаёт `experimentId`, но Calendar только
прокручивает к строке и оставляет остальные эксперименты на экране;
никакого визуального выделения тоже нет. Сделать период/номер недели в
колонке «Даты» `/experiments` второй точкой входа в тот же режим. В
сфокусированном режиме Calendar показывает лишь выбранный эксперимент
и явный контекст «Просмотр: {название}» с действием «Показать все
эксперименты». Это действие снимает фокус, но сохраняет открытое окно
недель. «Сегодня» в сфокусированном режиме меняет только окно недель,
не снимая выбранный эксперимент. Для week-tracked эксперимента
использовать первую реальную неделю; для legacy-эксперимента с
диапазоном дат — нормализованную начальную неделю. Недатированный
эксперимент остаётся с неинтерактивным значением «—».

**Acceptance Criteria:**
- Кнопка «Показать на календаре» на карточке и клик по заполненному
  значению в колонке «Даты» на `/experiments` открывают один и тот же
  сфокусированный режим Calendar только с выбранным экспериментом.
- Окно Calendar начинается с первой запланированной недели
  week-tracked эксперимента; legacy-эксперимент открывается с недели,
  содержащей его `startDate`.
- В сфокусированном режиме видны название выбранного эксперимента и
  явная кнопка «Показать все эксперименты»; она возвращает общий
  Calendar, сохраняя текущее окно недель.
- «Сегодня» в сфокусированном режиме сохраняет фокус на эксперименте,
  а в общем Calendar работает как прежде.
- «—» у эксперимента без дат не является ссылкой.
