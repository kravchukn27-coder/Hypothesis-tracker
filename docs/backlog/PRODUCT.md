## PROD-032 — Показать «Раскатку» в карточке эксперимента

- **Status:** TODO
- **Priority:** High
- **Area:** Product / Data model
- **Type:** Bug fix
- **Summary:** Поле «Раскатка» (PROD-030) сейчас редактируется только inline в Calendar и отсутствует на карточке эксперимента (`/experiments/[id]`) — добавить его туда, чтобы оба места читали и писали одно и то же значение согласованно.
- **Description:**
  PROD-030 добавил `Experiment.rollout` в схему и inline-редактирование в Calendar (`RolloutCell`, `updateExperimentRollout`), но карточка эксперимента (`ExperimentForm.tsx`, используется на `/experiments/[id]` и `/experiments/new`) про это поле не знает — не показывает его и не передаёт в основной `updateExperiment`. Из-за этого поле выглядит несинхронизированным: значение живёт только в Calendar, на карточке эксперимента такого понятия нет вовсе, и нет единого места, где видно все поля эксперимента разом. Нужно добавить «Раскатку» как обычное текстовое поле в `ExperimentForm` (секция «Основное», рядом с «Автор») и в его серверный `updateExperiment`/`createExperiment`, чтобы карточка и Calendar работали с одним и тем же значением через один и тот же путь сохранения.
- **Acceptance Criteria:**
  - На карточке эксперимента (`/experiments/[id]`, форма редактирования) есть текстовое поле «Раскатка», необязательное, как и в Calendar.
  - Сохранение через карточку и через inline-ввод в Calendar пишут в одно и то же поле `Experiment.rollout`; после сохранения в одном месте новое значение видно в другом без рассинхронизации.
  - Открытие карточки существующего эксперимента с уже заполненной «Раскаткой» (введённой через Calendar) показывает это значение в поле формы.
  - Пустое значение по-прежнему допустимо в обоих местах.
  - Не меняются Prisma-схема (поле уже существует), формула Score, связь Experiment→Hypothesis и остальные поля формы.

## PROD-031 — Убрать Experiments как отдельный экран, объединить с Calendar

- **Status:** TODO
- **Priority:** High
- **Area:** Product / Navigation
- **Type:** Simplification
- **Summary:** Оставить в приложении только Backlog и Calendar; Calendar становится основным инструментом работы с экспериментами, список `/experiments` и пункт навигации «Experiments» убираются.
- **Description:**
  Сейчас в приложении три экрана верхнего уровня — Backlog, Experiments (список `/experiments` + карточка `/experiments/[id]`) и Calendar. Список `/experiments` и одноимённый пункт навигации убираются целиком: вся функция «посмотреть все эксперименты», которую сейчас даёт список, переезжает внутрь Calendar как встроенный режим/переключатель «показать все эксперименты» (а не отдельный роут верхнего уровня). Существующий на Calendar блок «Без дат» для ещё не запланированных экспериментов не меняется — это отдельная, уже работающая часть экрана. Карточка `/experiments/[id]` остаётся как есть и как единственное место полного редактирования эксперимента, но перестаёт быть частью навигации: попасть в неё можно только по клику на название эксперимента — из строки Calendar или из карточки гипотезы в Backlog. Состав колонок строки эксперимента в Calendar (название, автор, раскатка — по PROD-030/UI-028) признан правильным и этой задачей не меняется. Часть полей, которые сейчас есть на `/experiments/[id]` (targeting-теги: funnel level, platform, channel, market, product, segment и т.п.), по мнению пользователя, по факту не нужны — их пересмотр и что именно убрать фиксируется как отдельная задача, не проектируется здесь.
- **Acceptance Criteria:**
  - Пункт навигации «Experiments» и список `/experiments` удалены из приложения.
  - В Calendar добавлен встроенный режим/переключатель «показать все эксперименты», по функции заменяющий прежний список `/experiments` (просмотр всех экспериментов, а не только ближайших недель).
  - Блок «Без дат» на Calendar не меняется этой задачей.
  - `/experiments/[id]` остаётся доступен как страница полного редактирования эксперимента, но без отдельного пункта меню — вход только через клик по названию эксперимента в Calendar или в карточке гипотезы Backlog.
  - Состав и вид колонок строки эксперимента в Calendar (название, автор, раскатка) не меняются.
  - Прямые ссылки на `/experiments/[id]` продолжают работать (не 404, не редирект на удалённый список).
  - Не меняются Prisma-схема, формула Score, обязательная связь `Experiment.hypothesisId → Hypothesis`, week-tracked доменная логика стадий и правила видимости (архив, скрытие Done).
  - Пересмотр/удаление конкретных targeting-полей на `/experiments/[id]` в эту задачу не входит — фиксируется отдельной карточкой при необходимости.

## PROD-029 — Добавить действие «Взять в работу» для Accepted-гипотезы

- **Status:** TODO
- **Priority:** Medium
- **Area:** Product / Workflow
- **Type:** Enhancement
- **Summary:** Создавать эксперимент из Accepted-гипотезы и открывать полный Calendar для ручного планирования.
- **Description:**
  В строке Backlog со статусом `ACCEPTED` показать действие «Взять в работу». Calendar ведёт только эксперименты, поэтому действие создаёт связанный с гипотезой эксперимент и переводит гипотезу в `IN_PROGRESS`. Затем открывается полный Calendar без фокусного `experimentId`, фильтров и заданной недели. Новый эксперимент отображается в блоке «Без дат» внизу Calendar и ждёт, пока пользователь перенесёт его на нужную неделю. Не создавать гипотезу как отдельную сущность Calendar и не обходить существующую обязательную связь «эксперимент → гипотеза».
- **Acceptance Criteria:**
  - Кнопка «Взять в работу» видна только у гипотез со статусом `ACCEPTED`.
  - Смена статуса на `ACCEPTED` не открывает отдельный диалог создания эксперимента; пользователь видит только кнопку в строке.
  - Нажатие создаёт ровно один связанный эксперимент из этой гипотезы и переводит гипотезу в `IN_PROGRESS` через существующий доменный workflow.
  - После создания открывается полный Calendar без `experimentId`, фильтров и заданной недели.
  - Новый эксперимент отображается в блоке «Без дат» и может быть перенесён пользователем на нужную неделю стандартным действием Calendar.
  - Повторное нажатие не создаёт дубликат, если для этой гипотезы уже есть незавершённый эксперимент; вместо этого открывается полный Calendar.
  - Не меняются Prisma-схема, формула Score и правило, что Calendar показывает эксперименты, а не гипотезы.

## PROD-027 — Быстрый поиск и фиксированные рабочие срезы таблиц

- **Status:** DONE
- **Priority:** Medium
- **Area:** Product / UI
- **Type:** Enhancement
- **Summary:** Дать команде быстрый способ находить нужные гипотезы и эксперименты и открывать частые выборки без отдельной системы сохранённых представлений.
- **Description:**
  Для базы до сотен записей добавить быстрый поиск в `/backlog` и `/experiments`, работающий вместе с существующими URL-фильтрами и сортировкой. В Backlog поиск охватывает название и Comment; в Experiments — название. Добавить несколько фиксированных, понятных рабочих срезов, подходящих текущей модели (например, гипотезы без эксперимента и активные/завершённые эксперименты), но не создавать пользовательские сохранённые представления или новую модель данных. URL остаётся единственным источником состояния фильтра и поиска, поэтому любой срез можно открыть и сохранить в закладках. Массовая смена статуса явно не входит в scope.
- **Acceptance Criteria:**
  - `/backlog` позволяет быстро отфильтровать строки по названию гипотезы и Comment; `/experiments` — по названию эксперимента.
  - Поиск корректно сочетается с текущими URL-фильтрами, сортировкой, архивным видом и существующей навигацией между гипотезой и экспериментом.
  - Пустой результат поиска объясняет, что совпадений нет, и даёт понятный путь сбросить поиск/фильтры.
  - Добавлены только фиксированные системные быстрые срезы для частых рабочих сценариев; пользовательские сохранённые view, их настройка и хранение не создаются.
  - Поиск и срезы полностью кодируются в URL, остаются ссылочными и работают после перезагрузки страницы.
  - Для week-tracked экспериментов срезы по текущему статусу используют тот же источник текущей стадии, что таблица и Calendar; legacy-эксперименты используют своё скалярное поле.
  - Не добавляются массовая смена статуса, Prisma-схема, новые доменные сущности или отдельный client-side источник состояния списка.

## PROD-026 — Summary карточки гипотезы и синхронизация её статуса с экспериментами

- **Status:** TODO
- **Priority:** Medium
- **Area:** Product / UI
- **Type:** Enhancement
- **Summary:** Сделать карточку гипотезы экраном чтения контекста с единым summary, next action и предсказуемой синхронизацией статуса со связанными экспериментами.
- **Description:**
  Карточка `/backlog/[id]` используется главным образом для чтения гипотезы и перехода к дополнительной информации; основной inline-статус остаётся в Backlog-таблице. Добавить в верхней части неизменяемый summary: статус гипотезы, Score, Funnel Level, связанный эксперимент с его текущей стадией, Result при завершении и один контекстный next action. Без эксперимента next action создаёт эксперимент; с незавершённым — ведёт к эксперименту или его календарному плану; после завершения проверки предлагает архивировать гипотезу. Статус гипотезы должен синхронизироваться с текущими стадиями связанных экспериментов: при наличии хотя бы одного незавершённого эксперимента — `IN_PROGRESS`; когда все связанные эксперименты завершены — `DONE` с предложением архивирования. Для week-tracked эксперимента используется та же текущая стадия, что в списке и Calendar; legacy-эксперимент продолжает использовать своё скалярное поле. Существующая форма и модель данных сохраняются.
- **Acceptance Criteria:**
  - Верх карточки содержит status, вычисляемый Score, Funnel Level, Result при наличии и один контекстный next action; summary не дублирует редактируемую форму ниже.
  - Для одной связанной проверки summary показывает эксперимент и его текущую стадию; при нескольких показывает их количество и понятное состояние без сокрытия связи.
  - Без эксперимента основной next action создаёт эксперимент из этой гипотезы.
  - При наличии хотя бы одного эксперимента с текущей стадией не `DONE` статус гипотезы становится `IN_PROGRESS`; summary ведёт к релевантному эксперименту или его Calendar-контексту.
  - Когда все связанные эксперименты находятся в `DONE`, статус гипотезы становится `DONE` и пользователю предлагается обратимое архивирование.
  - Синхронизация работает одинаково при изменении стадии из списка Experiments, карточки эксперимента и Calendar, не создавая второй источник истины для week-tracked эксперимента.
  - После удаления последнего эксперимента сохраняется действующее правило возврата гипотезы в `NEW`.
  - Не меняются Prisma-схема, формула Score, набор существующих полей и desktop-first подход.
