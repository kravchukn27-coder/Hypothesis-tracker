## PROD-036 — Ручная сортировка (drag-to-reorder) экспериментов в столбце «Эксперимент» на Calendar

- **Status:** TODO
- **Priority:** Medium
- **Area:** Product / Calendar
- **Type:** Enhancement
- **Summary:** В таймлайне Calendar (`src/app/calendar/page.tsx`) пользователь хочет захватывать курсором строку эксперимента в левой колонке «Эксперимент» и перетаскивать её вверх/вниз внутри списка, задавая тем самым ручной приоритет отображения — независимо от текущей сортировки по датам.
- **Description:**
  Голосовой запрос пользователя: возможность вручную поднять/опустить эксперимент в списке строк Calendar, как способ задать приоритет.

  Сегодня порядок строк в Calendar — не ручной, а вычисляемый: Prisma-запрос сортирует эксперименты `orderBy: [{ startDate: { sort: "asc", nulls: "last" } }, { createdAt: "desc" }]` (`page.tsx`), и никакого поля для ручного порядка в модели `Experiment` нет (`prisma/schema.prisma`). Чтобы drag-to-reorder был устойчивым (сохранялся между перезагрузками, не конфликтовал с сортировкой по дате), нужно **новое поле** в модели `Experiment` — например `manualOrder: Int?` (или отдельная таблица порядка) — и переключение сортировки строк на это поле, когда оно задано, с осмысленным fallback на текущую сортировку по дате для экспериментов без ручного порядка. Это меняет модель данных, поэтому по правилам проекта (`docs/backlog/WORKFLOW.md`) оформляется отдельной задачей, а не как часть чисто визуальных Calendar-тикетов (UI-047…UI-053).

  Открытые вопросы для уточнения при реализации:
  - Ручной порядок — глобальный (один и тот же порядок эксперимента везде, где он показан) или локальный только для Calendar-таймлайна?
  - Как ведёт себя ручной порядок при смене окна недель (`?start=`) или при переключении в «Показать все эксперименты» (`AllExperimentsTable.tsx`, у которой уже есть собственная сортировка по колонкам, `sortBy`/`dir`) — сосуществуют ли два механизма сортировки или ручной порядок специфичен только для этого экрана?
  - Что происходит с порядком у только что созданного эксперимента (в конец списка? в начало?).
- **Acceptance Criteria:**
  - В левой колонке «Эксперимент» на Calendar-таймлайне строку можно захватить курсором (drag handle или вся строка) и перетащить выше/ниже других строк в текущем видимом окне.
  - Новый порядок сохраняется на сервере (переживает `router.refresh()`/перезагрузку страницы) — реализовано через новое поле в модели `Experiment` (Prisma) или эквивалентный персистентный механизм.
  - Порядок эксперимента без явного ручного приоритета продолжает определяться существующей логикой (`startDate` asc / `createdAt` desc), не ломается для экспериментов, которые никто не перетаскивал.
  - Drag-to-reorder не конфликтует с уже существующим drag-and-drop на этом экране — перетаскивание недатированных экспериментов на неделю (`UndatedRow` → `WeekHeaderCell`, `dataTransfer.setData("text/plain", experimentId)`) и drag-to-move/resize стадийных блоков внутри `ExperimentWeekRow` — три разных жеста должны различаться однозначно (например, по зоне захвата — drag-handle слева в колонке «Эксперимент» против самих стадийных плашек).
  - `prisma/schema.prisma` меняется только в рамках этой задачи (новое поле/таблица для ручного порядка), с `npx prisma db push` по текущему процессу синхронизации схемы (см. `docs/PROJECT_CONTEXT.md` → Local Development).
  - Поведение не переносится на Backlog/Experiments — это Calendar-специфичная сортировка, если при реализации не решено иначе (см. открытые вопросы выше).

## PROD-030 — Добавить текстовое поле «Раскатка» к эксперименту

- **Status:** TODO
- **Priority:** Medium
- **Area:** Product / Data model
- **Type:** Enhancement
- **Summary:** Хранить у эксперимента свободный текст «Раскатка» для операционного контекста в Calendar.
- **Description:**
  Добавить к эксперименту необязательное текстовое поле «Раскатка». Значение редактируется inline в Calendar и сохраняется у эксперимента; это не тег, не фильтр и не новая сущность.
- **Acceptance Criteria:**
  - Эксперимент хранит необязательное текстовое значение «Раскатка».
  - Значение можно изменить из строки Calendar без перехода на другую страницу.
  - Текст сохраняется по Enter или при уходе из поля, после чего Calendar показывает сохранённое значение; пустое значение допускается.
  - Не меняются связи гипотез, экспериментов, стадий и существующие категории тегов.

## PROD-027 — Быстрый поиск и фиксированные рабочие срезы таблиц

- **Status:** DONE
- **Priority:** Medium
- **Area:** Product / UI
- **Type:** Enhancement
- **Summary:** Дать команде быстрый способ находить нужные гипотезы и эксперименты и открывать частые выборки без отдельной системы сохранённых представлений.
- **Description:**
  Для базы до сотен записей добавить быстрый поиск в `/backlog` и `/experiments`, работающий вместе с существующими URL-фильтрами и сортировкой. В Backlog поиск охватывает название и Comment; в Experiments — название. Добавить несколько фиксированных, понятных рабочих срезов, подходящих текущей модели (например, гипотезы без эксперимента и активные/завершённые эксперименты), но не создавать пользовательские сохранённые представления или новую модель данных. URL остаётся единственным источником состояния фильтра и поиска, поэтому любой срез можно открыть и сохранить в закладках. Массовая смена статуса явно не входит в scope.
- **Acceptance Criteria:**
  - `/backlog` позволяет быстро отфильтровать строки по названию гипотезы и Comment; `/experiments` — по названию эксперимента.
  - Поиск корректно сочетается с текущими URL-фильтрами, сортировкой, архивным видом и существующей навигацией между гипотезой и экспериментом.
  - Пустой результат поиска объясняет, что совпадений нет, и даёт понятный путь сбросить поиск/фильтры.
  - Добавлены только фиксированные системные быстрые срезы для частых рабочих сценариев; пользовательские сохранённые view, их настройка и хранение не создаются.
  - Поиск и срезы полностью кодируются в URL, остаются ссылочными и работают после перезагрузки страницы.
  - Для week-tracked экспериментов срезы по текущему статусу используют тот же источник текущей стадии, что таблица и Calendar; legacy-эксперименты используют своё скалярное поле.
  - Не добавляются массовая смена статуса, Prisma-схема, новые доменные сущности или отдельный client-side источник состояния списка.
